# Documentation

## 表記規則

ドキュメントを記述する際は、以下の表記規則に従う。

- ファイル名は英語のkebab-caseで命名する。
- 見出しには番号を付与しない。
- 区切り線は利用しない。
- 太字の使用は必要最低限に抑える。
- コードブロックでシェルコマンドを扱う際は、bashではなくshellを利用する。
- 表を利用する場合、ヘッダーの区切り線は各列ともハイフンもしくはコロン3つの組み合わせとする。
  - 例： `---` , `:--` , `:-:` など。
- 箇条書きや表、Mermaid Diagramなどから説明を始めるのではなく、文章で説明を始める。

例：

```markdown
## 命名規則

変数名を定める際は、以下の規則に従うこと。

- camelCaseに従うこと。
- できる限りシンプルな単語、もしくは単語の組み合わせとすること。
```

## 図の作成

フローチャートやデータフロー、ロジックツリーなどを描画するよう求められた際は、常にMermaid形式で作成する。Mermaidを作成する際は、以下の制約に従う。

- 物理名（変数）はcamelCaseの英語、論理名（表記）は日本語で、1語もしくは2語のなるべくシンプルな単語とする。
- CSSによるスタイリングは適用しない。
