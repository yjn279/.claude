# Rubric Generation

書き手の文体を、規則の記述（ルーブリック）として書く、または更新する言語モデル呼び出しである。初回の作成と以降の更新は同一の処理であり、プロンプトを分けない。初回は「前回のルーブリック」と「判定根拠」が空になる。

このルーブリックが、学習ループで唯一更新される**パラメータ**（最適化の対象）である。条件抽出・Generator・Discriminatorの各呼び出しはいずれも固定であり、更新されない。

この呼び出しはメモリ機能を使わない。過去の**エポック**（1ラウンド。1回分の生成・判定・ルーブリック更新からなる）についての記憶を参照せず、以下に渡された入力だけを文脈とする。エポックをまたいで持ち越してよい状態はルーブリックだけであり、それは「前回のルーブリック」として明示的に渡される。

## Input

| 入力 | 役割 |
| :-- | :-- |
| 学習データ | 文体の観測元。初回も更新時も必要 |
| 前回のルーブリック | 更新の起点。初回は空 |
| 判定根拠 | 1エポック分の判定バッチ（本人の文章と生成文を半々に混ぜた1回分の判定対象群）でDiscriminatorが出力した根拠の一覧。**勾配**（数値ではなく言語で表現された更新方向）にあたる。更新の方向を示す。初回は空 |

```
<training_data>
（ここに学習データの全件を貼り付ける）
</training_data>

<previous_rubric>
（初回は空。2エポック目以降は前回出力したルーブリックの全文を貼り付ける）
</previous_rubric>

<verdict_reasons>
（初回は空。2エポック目以降は、直近のバッチでDiscriminatorが出力した判定根拠を1件1行で列挙する）
</verdict_reasons>
```

## Output

次の8項目からなるルーブリックを、Markdown で出力する。各項目には、観測頻度（どのくらいの割合や頻度で現れるか）、ごく短い例示（数語程度の断片。原文を長く転記しない）、逸脱の許容範囲（どこまでの逸脱を許すか）を記す。

- 語彙と語形
- 統語とリズム（一文の長さの分布、体言止めの頻度など）
- 表記と記号と改行
- 論理展開の型
- 態度とスタンス
- 話題選好
- 長さの分布
- 禁則（この書き手が絶対にやらないこと）

出力の末尾に、今回のバッチ（1エポックでDiscriminatorにかけるサンプルの集まり）で採用した特徴と捨てた特徴の件数を記す。

## Update Procedure

前回のルーブリックと判定根拠がある場合（2エポック目以降）の手順は次のとおり。

1. `<verdict_reasons>` に列挙された全判定根拠を、言及された特徴ごとに正規化して数え上げる。
2. バッチ内で、バッチサイズの15%以上（目安。バッチサイズが渡されていない場合は3件）のサンプルに共通して現れた特徴だけを更新対象とする。それに満たない言及は個別サンプルのノイズとして捨てる。
3. 出現頻度の高い順に、前回のルーブリックの該当項目を修正する。
4. 判定根拠に一度も現れなかった項目は、統合または削除の候補とする。ルーブリックの肥大はGeneratorの注意を薄め、かえって精度を落とす。

初回（`<previous_rubric>` と `<verdict_reasons>` が空）は、上記の更新手順を使わず、学習データだけを観測して8項目を一から書く。

## Constraints

- 例示は数語程度の断片に留める。原文を長く転記すると、Generatorがフレーズをそのまま再利用し、特定の文だけ似ている状態になって汎化しない。ルーブリックは事例集ではなく規則の記述である。
- 検証データの本文をルーブリックに書き込まない。更新の材料は判定根拠であって正解文ではない。混ぜると検証データへの過適合が起きる。
- 採用した特徴と捨てた特徴の件数を出力の末尾に必ず残す。
