# Condition Extraction

検証データ（コーパスを7:2:1に分けたうちの1つ）に含まれる文章から、内容の骨子だけを逆抽出し、**条件入力**（文章のネタ。生成する文章が何について書くかを指定する入力）を作る。「何を言っているか」は残し、「どう言っているか」（語彙・語順・言い回し・句読点の癖・トーン）は捨てる操作である。

この操作が必要なのは、後段のGenerator（ルーブリックと条件入力を読んで文章を書く言語モデル呼び出し）に、本人と同じ題材で書かせるためである。題材が違うと、Discriminator（見本を参照し、提示された1件の文章が本人の筆か生成文かを判定する言語モデル呼び出し）は文体ではなく話題の違いで見分けてしまい、測っているものが文体でなくなる。

この呼び出しはメモリ機能を使わない。過去に扱った文章についての記憶を参照せず、以下に渡された入力だけを文脈とする。

## Input

検証データに含まれる文章のうち、1件の本文全文。

```
<source_text>
（ここに検証データの1件の本文を貼り付ける）
</source_text>
```

## Output

主張・事実・トピックだけを箇条書きにしたもの。各項目は平易で無個性な一般語に置き換え、元の語彙・言い回し・句読点の癖・トーンを残さない。

出力形式：

```
- （主張・事実・トピック1）
- （主張・事実・トピック2）
...
```

例：

> 元の文章：正直、あの映画は期待外れだった。脚本が雑すぎる。
>
> 条件入力：
> - ある映画の感想
> - 期待に届かなかった
> - 理由は脚本の粗さ

## Constraints

- 語彙・語順・言い回し・句読点の癖・トーンをいずれも残さない。原文の言い回しをそのまま使わない。
- 主張・事実・トピック以外（感想の強さの演出、比喩、修飾）は含めない。
- 元の文章の断片を引用しない。すべて平易な一般語に言い換える。
- ここで作った条件入力は、この文章に対して一度だけ作成し、以降のすべてのエポック（1ラウンド。1回分の生成・判定・ルーブリック更新からなる）を通じて固定して使い回す。エポックごとに取り直さない。
