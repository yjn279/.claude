# Git Flow

このリポジトリにおける git の運用ルールを定める。対象は新規リポジトリの初期化と、作業ブランチの作成の2つである。

## Git Init

新しいリポジトリを作成する際は、基本的にパブリックとして公開する。デフォルトブランチ名は `main` とし、`master` は使わない。

リポジトリ作成直後は、次のコマンドで空コミットを作成する。

```shell
git commit --allow-empty -m "Initial commit"
```

`main` ブランチは直接作業しない。機能追加や修正など実際の作業は、`main` から作業ブランチを切って進める。

## Git Branch

ブランチ名は `<type>/<description>` の形式とする。`<type>` はそのブランチで行う変更の種類を表し、`<description>` は変更内容を表す kebab-case の英語短句とする。

`<type>` の代表例は以下のとおりである。

- `feat`: 新機能の追加
- `fix`: バグ修正
- `chore`: ビルドやツールなど、コードに直接関係しない変更
- `docs`: ドキュメントの変更
- `refactor`: 動作を変えないコードの整理・改善
- `test`: テストの追加や修正
